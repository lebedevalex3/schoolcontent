# School Content: внешнее хранилище материалов

## Git и готовые файлы

- Git хранит исходники и описание материалов.
- Готовые PDF, PPT/PPTX, видео и аудио игнорируются Git и хранятся на
  Яндекс.Диске.
- Корень каталога готовых материалов на Яндекс.Диске — `School Content`.
- Пути на Диске повторяют относительные пути в репозитории. Например,
  `EGE/presentations/lesson/outputs/main.pdf` публикуется как
  `School Content/EGE/presentations/lesson/outputs/main.pdf`.

## Публикация на Яндекс.Диск

Для загрузки готовых материалов использовать:

```bash
scripts/publish-yandex-disk.sh EGE
scripts/publish-yandex-disk.sh school/5grade/01_NaturalNumbers
```

Без аргументов команда публикует все PDF, PowerPoint, видео и аудио в
репозитории:

```bash
scripts/publish-yandex-disk.sh
```

Манифест `.secrets/yandex-disk-manifest.tsv` хранит SHA-256-хэши успешно
загруженных файлов. Поэтому неизменившиеся файлы не передаются повторно, а
изменённый файл с тем же относительным путём обновляет соответствующий файл на
Яндекс.Диске. Команда не удаляет файлы из облака, в том числе старые файлы
после переименования. Для полной повторной загрузки используется
`scripts/publish-yandex-disk.sh --force <путь>`.

Для уже подтверждённо выгруженных материалов без записей в манифесте можно
один раз выполнить `scripts/publish-yandex-disk.sh --adopt-existing <путь>`.
Этот режим не обращается к Яндекс.Диску, а лишь записывает локальные хэши;
использовать его только когда версии в облаке и локально заведомо совпадают.

Перед публикацией убедиться, что локально создан файл
`.secrets/yandex-disk.netrc` с паролем приложения WebDAV. Секреты нельзя
показывать в сообщениях, добавлять в Git или записывать в документы проекта.

После генерации новых или изменённых PDF при явном запросе пользователя на
синхронизацию запускать публикацию соответствующего раздела. Если пользователь
просит только сгенерировать файл, не загружать его в облако без запроса.
